## 0. 미션 (헌법 — 절대 불변)

**ADA는 사용자가 준 _임의의_ 데이터에 맞는 보고서를 생성한다 — 4카테고리: 정형 ML · 정형 DL · 시계열 · 이상탐지.**
사용자가 무슨 데이터를 줄지 아무도 모른다. **타이타닉 / telco 는 개발용 테스트 데이터일 뿐, 목표가 아니다.**
모든 룰은 특정 데이터가 아니라 **구조·카테고리 분기**로 일반화돼야 하며, **임의 값(컬럼·숫자·문장) 하드코딩은 금지**다.

### 0-1. 핵심 산출물의 격 (格) — 절대 기준

- **Executive Summary = 회장이 3초 보고 찢어가는 1페이지.** 답(BLUF) → 왜(3기둥: 무엇이 가르나·얼마나 믿나·얼마짜리인가) → 증거(hero exhibit) → 권고(now-what) → 단서가 **한 장에 완결**. 산문 단락이 아니라 **구조화 신서시스(맥킨지 피라미드 원칙)**. *이 페이지만으로 의사결정이 끝나야 한다.* 여백 주는 페이지가 아니라 꽉 채우는 페이지.
- **Exhibit = 본문 주장을 뒷받침하는 시각 한 덩어리.** **5요소 필수**: ①번호 ②**Takeaway title(결론 문장)** ③비주얼 ④단위·기간 ⑤출처·n·주(정의·한계). Takeaway가 왕(제목만 읽어도 논리가 흐름). **자리값 못하면 금지**(쓸데없는 시각 0).
- **비즈니스 KPI ≠ 모델 지표 (둘 다 필수, 자리가 다름).** 회장이 보는 건 *임팩트*(매출·비용·감축·식별률)지 AUC·F1이 아니다. **KPI는 '왜·인사이트'와 동급으로 중요.** 배치: **Exec hero exhibit = 비즈니스 KPI/임팩트**(business_kpi + 투영) · **§5 모델 성능 = 모델 지표**(AUC·F1 = "믿어도 되나") · **§7 비즈니스 임팩트와 실행 = 상세 KPI·ROI**. 모델지표를 KPI로 착각 금지(현 Exec가 AUC를 hero로 쓰던 것을 비즈니스 KPI로 교체).
- **형식/내용 분리 원칙:**
  | 요소 | 형식(carrier) | 내용(skeleton) | 데이터(builder/ctx) |
  |---|---|---|---|
  | Exhibit 번호 | ✅ 부여·배치 | | |
  | Takeaway title | 슬롯·스타일 | ✅ 결론 도출 | 근거 수치 |
  | 비주얼 | ✅ 차트 종류·스타일 | 어떤 시각인지 선택 | ✅ 값 |
  | 단위·기간 | 배치 | ✅ 문구 | ✅ 값 |
  | 출처·n·주 | 배치 | ✅ 정의·한계 | ✅ n |
  - 즉 **틀·레이아웃 = 형식, 결론·해석·정의 = 내용, 실제 값 = 데이터.** 가짜 수치 0(전부 ctx). 절차: 내용(skeleton)이 패키지를 만들고 → 형식(carrier)이 격자에 앉힌다.

### 0-2. 데이터 불문 자동 연결 + 70/30 레지스터 (절대 기준)

- **Use-All-Assets (조건부 노출):** 어떤 데이터가 들어와도(ML·DL정형·시계열·이상치, 사용자 1만 명 제각각) **ctx에 자산이 있으면 자동 노출, 없으면 조용히 스킵(에러 0).** 패턴 `if ctx.<asset>: render(...)` + **카테고리 분기**(ML=혼동행렬, 시계열=계절성, 이상치=임계값…). 보고서 = 가능한 모든 자산을 켜 둔 **superset 템플릿**. 특정 데이터(타이타닉) 가정 금지. 파이프라인·에이전트·ctx 필드는 **있는 대로 다 끌어다 쓴다**(현재 ~60% → 100% 지향).
- **오디언스 적응형 70:30 + 본문/부록 레지스터:** 보고서는 **기본 30% 데이터분석 · 70% 비즈니스 의사결정**, 단 비율은 **청중에 따라 70:30을 닻으로 자동 조절**: C레벨 80:20, 부서장 70:30(기준), 분석가 55:45, 외부 75:25. 조절값은 `ctx`의 **`audience_inference`(이미 추론된 숨은 자산)** 가 정함(사람이 손대지 않음). **레지스터 분리는 청중 불문 항상 유지:** **본문**(비즈니스 결정 = so-what + 핵심 숫자 1개 + 쉬운 말) / **부록**(100% 기술 = 통계·방법론·진단·전체 표·가정), 본문에 "상세: 부록 §9.x" 링크. (계층적 공개: 임원은 본문 3초·30초, 검증자는 부록 정독.)
- **구현(.py, 검증됨):** `report_skeleton.audience_register(ctx)` → `{audience, body_pct, appendix_pct, depth}` 반환(단위테스트 7케이스 통과). 모든 자산은 `reg = audience_register(ctx)` 후 `reg['depth']`(`decision`|`balanced`|`technical`)로 본문형(so-what)/부록형(기술) 비중 결정. chairman_exec 결과물에 `register` 키로 동봉.

## C. 내용 룰 — 문서가 무엇을 말하는가 (7개)

### C-1. 문서 전체 관통 메시지 (3개)

#### C1. [관통질문룰 — 피라미드 원칙]
- 출처: 본 대화 (Barbara Minto, Pyramid Principle)
- **핵심:** 문서 전체가 답하는 **단 하나의 관통(governing) 질문**을 세우고, 나머지는 전부 그 아래로 줄세운다(MECE 분해). **같은 층위의 경쟁 질문 금지 = "질문 수프" 금지.**
- **구조(피라미드):**
  - ① 헤드라인 = 관통 질문(apex, 의사결정형)
  - ② 핵심(so_what) = 그 질문을 가르는 **'기준' 진술**(경쟁 질문이 아니라 기준)
  - ③ 세부 질문 = 관통 질문의 **MECE 분해**(서로 안 겹치고, 합치면 관통 질문에 답함)임을 한 줄로 명시
- **반복(through-line):** 관통 질문은 표지·Exec Summary·각 섹션 논제·§8 답으로 반복 — 질문(§1)↔답(§8) bookend. 모든 섹션은 이 질문에 답하는 한 조각.
