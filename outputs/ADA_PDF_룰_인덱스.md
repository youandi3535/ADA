# ADA PDF 룰 인덱스 · 코드 동기화 추적표 (SYNC TRACKER)

> **이 파일의 목적**: 룰(.md)이 실제 코드(.py)에 반영됐는지 1:1로 추적하는 **단일 상태판**.
> 룰 문서(`ADA_PDF_하드코딩_룰.md`)는 "무엇을"을 적고, 이 인덱스는 "코드 어디에, 반영됐나, 렌더로 확인했나"를 적는다.
> **드리프트(md엔 있는데 코드엔 없음) 방지 = 이 표가 핵심.** 매 작업 후 NY가 갱신한다.
>
> 상태 범례: ✅ 코드반영+렌더확인 · 🟡 부분/미검증 · ❌ md만 있고 코드 미반영
> 최종 감사: 2026-06-12 (실렌더 `dev_preview3 titanic`, 17p 기준) · 룰명 앵커링크 추가 + 개수 정정(50→43)
>
> 🔗 **링크 사용법**: 아래 표의 룰명(B1~B31·C1~C7)을 클릭하면 `ADA_PDF_하드코딩_룰.md`의 해당 룰 섹션으로 바로 이동합니다.
> 앵커는 **GitHub/VS Code 슬러그 규칙** 기준(소문자·공백→하이픈·점/대괄호 제거). VS Code는 마크다운 미리보기(Ctrl+Shift+V)에서 클릭하세요.

## ★ 미션 (헌법 — 절대 불변, 최우선으로 읽을 것)

**ADA는 사용자가 준 _임의의_ 데이터에 맞는 보고서를 자동 생성한다. 사용자가 어떤 데이터를 줄지 아무도 모른다.**

- 대상 카테고리 **4종: 정형 ML · 정형 DL · 시계열 · 이상탐지.**
- 모든 룰·코드·골든·테스트는 **이 4종 + 임의 데이터에 일반적으로** 성립해야 한다.
- ⚠️ **타이타닉 / telco 는 "개발용 테스트 데이터"일 뿐, 목표가 아니다.** 특정 데이터 맞춤 보고서를 만드는 게 아니다.
- → **임의 값 하드코딩 금지** (특정 컬럼명·숫자·문장 박지 말 것). 룰 = 구조·카테고리 분기, 내용 = `ctx` 에서.
- 골든은 "정답"이 아니라 ① **모든 입력에 참인 불변식(invariant)** + ② **카테고리별 회귀 가드(픽스처)** 로 나눠 설계한다. (타이타닉 = tabular-clf 대표 픽스처 1개)

> 이 미션은 `CLAUDE.md`(진짜 헌법, HJ 영역)에도 올라가야 함 — HJ 협의 항목.

## 0. 세계기업 관점 — 이 문서 구조를 왜 이렇게 짰나

대형 컨설팅·디자인시스템(맥킨지 보고서 표준, Google Material, IBM Carbon, Economist 스타일가이드)의 공통 패턴:

1. **구조(Structure)와 내용(Content)을 분리한다.** 레이아웃·그리드·타이포·간격은 "디자인 파운데이션", 톤·논리·비즈니스 메시지는 "에디토리얼 가이드". 둘은 **바뀌는 속도와 담당 사고방식이 다르다.**
2. **추적 매트릭스(Traceability)를 둔다.** 요구사항 → 구현 위치 → 검증, 이 3열 매핑이 모든 성숙한 사양서의 핵심. **드리프트를 잡는 건 산문이 아니라 이 표다.**
3. **풍부화 매트릭스 같은 "무슨 내용을 넣나"는 내용(Content) 쪽**이다 — 구조 룰과 섞지 않는다.

→ **권고 구조 (NY는 1인 종주이므로 파일 과분할은 피함):**

| 파일 | 성격 | 담는 것 |
|---|---|---|
| `ADA_PDF_룰_인덱스.md` (이 파일) | **상태판/추적** | 전 룰 ↔ 코드 위치 ↔ 반영상태 (단일 진실) |
| `ADA_PDF_하드코딩_룰.md` | 사양(무엇을) | A 메타 / **B 구조** / **C 내용** — 기존 유지 |
| `ADA_PDF_본문_풍부화_매트릭스.md` | **내용(Content) 백로그** | 정공 10요소×8섹션 — C(내용) 룰의 확장. 구조와 섞지 않음 |

즉 **물리적 파일을 잘게 쪼개기보다, 이 인덱스가 "구조/내용/메타"를 열로 나눠 추적**한다. 1인 유지보수엔 이게 세계기업식 "단일 진실 출처 + 추적성"에 가장 부합한다. (팀이 커져 레이아웃 담당과 에디토리얼 담당이 갈리면 그때 파일 분할.)
